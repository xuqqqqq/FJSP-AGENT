# 工业 Skill 的从零构造缺口核查

日期：2026-09-08。用户要求继续测试 300 任务，并询问已有工业 Skill 为什么未能复现旧算法能力。本记录核对原 Skill、当前适配版和已结束的 500 任务实验；300 任务结果另记测试台账。不修改冻结 Skill、生产代码、输入或评价器。

## 已确认的事实

1. 上游 `huawei_fjsp_llm/.codex/skills/huawei-aluminum-fjsp/SKILL.md` 第 49 行起列出 preset solver、有限批校验器及参数调优工具，第 140 行起要求先有合法 baseline，再搜索派工参数。它记录了已有求解器的使用、调参及诊断流程，没有展开从零合法构造、资源撤销、最大 Q-time 回修的完整步骤。旧求解器具有某项能力，不等于 Skill 文本已包含实现该能力所需的知识。
2. 当前 `.codex/skills/huawei-aluminum-fjsp/SKILL.md` 保留了前瞻、重量密度、截止紧迫度、换型连续性、有限批等待/成员选择和有界扰动；第 49--54 行指出上界 Q-time 冲突可能要求修订链的前段。但这些内容主要是机制要求，缺少可直接验收的构造和回退状态流程。第 44 行仍以保留已有 parser、decoder、incumbent 为起点。
3. `outputs/iz500a/large500_final_audited.md` 及对应 JSON 证明 Full 三次均实际加载该 Skill，None 均未加载。成功加载证明资料投递，不能证明代码已实现相应机制。
4. 500 Full 最终候选 `outputs/iz500a/full/total_round_002/candidate_worktree/examples/agent_generated_industrial_solver.py` 第 554 行附近的 `_qtime_delay_repair` 对上界冲突留有 no-op；第 588 行附近 `_apply_shift` 统一平移整条路线。对固定机器分配与工时，所有链内锚点加相同偏移不改变锚点差，因而这种平移本身不能修复链内 Q-time 超界。此结论针对该修复分支，不表示任何链平移在资源排布中都无用，也不表示输入必然不可行。
5. 500 Full 首轮 `worker_assignment.json` 第 105 行禁止 Beam、多起点、局部搜索；第 197 行 `activation_checks` 为空。当前 `harness_agent/context/worker.py` 的基础任务完成规则仍有同样限制。它把许多搜索手段放到合法基线之后，而复杂约束下找到首个合法解本身可能需要有界搜索。
6. 500 两侧每轮均只有 4 编辑步、1 次最多 3 秒 schema smoke；三轮包含初始生成和修复。六次实际失败均为运行错误，没有拿到完整合法输出。不能将这些错误归因为已经用尽 60 秒求解预算后的质量停滞。

## 解释边界

证据支持“旧经验没有被完整转化为从零构造说明，且生成代码未落实部分明确要求”。不能据此断言模型永远学不会，也不能把任务规模、任务书限制、上下文、修复预算或模型能力中的任何一项认定为唯一根因。

基础阶段禁止若干搜索手段，是值得验证的流程假设；尚未做放宽限制的受控实验，不能承诺解除限制即可求解。`activation_checks=[]` 不意味着平台完全没有其他门禁：固定 Core 确实拒绝了这些失败候选。缺口在于失败前的实现检查及反馈修复未能让代码在三轮内完成合法构造。

- 区分“为合法性必要的有界搜索”和“已有合法解后的质量优化”，验证基础任务书是否应允许前者。
- 对关键修复机制要求可达代码及失败分支证据，例如上界冲突后是否真正重排锚点、是否回滚资源占用；不能用 helper 名称、注释或加载日志代替实现证据。
- 单独冻结改进版本，用相同实例、轮次和评价器复测，保留当前失败，不与正在运行的 300 任务原配置对照混合。

本次核查没有修改或运行上游求解器；上游 Skill 中工具名称只用于辨别其原本用途。

- None 第二轮也没有上界 Q-time 回退：构造时施加下界，完整构造后检查上下界，失败则抛错。其成功只证明本次机器和排序选择找到了合法路径，不能说它实现了更强的 Q-time 修复。
- Full 首轮比较许可机器的可行空档，逐步选最早完工的安置；无候选即返回失败，没有撤销上游决策重试。实际报错为 `YT1032 / 0 / 3` 无可行机器。证据：`outputs/iz300a/full/total_round_000/worker_loop/agent_generated_baseline/candidate_worktree/examples/agent_generated_industrial_solver.py:168`、`:275`、`:309`，以及该轮 Core solver stderr。
- Full 首轮未给出逐台候选机器的拒绝原因，故不能将这次失败唯一归因于 Q-time，也不能用它证明输入不可行。本例 Q-time 锚点均为 `end-start`，其他锚点处理的潜在缺陷不能拿来解释本次失败。
- 两组不同贪心选择产生了不同结果。None 的合法结果说明本例存在简单构造可走通的路径，不能据此证明回溯必需；“增强回退能提高稳定性”仍需独立受控实验。

## 300 Full 第二轮：诊断耗尽步骤而没有修复

第二轮 Worker 正常退出，`changed_files=[]`，候选源码与首轮完全一致，Core 仍报 `YT1032 / 0 / 3` 无可行机器。该轮完整墙钟为 674.422 秒，不是 Worker 900 秒超时。

运行配置 `outputs/iz300a/full/total_round_001/worker/opencode_runtime_config.json` 中 `agent.algoforge-worker.steps=12`；事件文件实际有 12 个 `step_finish`，无 edit/write 工具事件。成功事件包括三次 Skill 加载、九次 read、两次 bash 检查，另有失败命令/检索；一模型步骤可能包含多个工具调用，不能把这些调用数简单相加当作步骤数。最终文字明确承认步骤耗尽、尚未编辑，仅提出后续修复建议。

配置来源是 `harness_agent/workers/opencode_worker.py:665`：任务的 `max_steps=4` 乘以 3，并受上下限截取后成为 OpenCode 总步骤数。这个限制覆盖读取、编辑和检查，不能将任务书的“4 编辑步”理解成读取完成后仍保留四次编辑机会。

这提供了一项独立于算法优劣的执行缺口：修复预算已消耗，但没有候选修改。后续应验证能否为实际编辑与最终检查保留步骤，并缩短重复读取；不能仅延长墙钟超时，也不能将未执行的建议算成已尝试的修复方法。该改进本轮未实施，不修改当前配对的冻结预算。

## 新 Skill 直接接入后的独立复测（iz300b）

此节是后续新批，不修改上述历史结论。项目工业包在保留旧 Skill 的基础上接入 `industrial-fjsp-from-scratch`，仅增加 Harness/IO/评价器权限边界，六份算法 references 保持来源内容。None 和 Full 重新各自从零、各三轮，同一 300 任务算例；配对审计通过。Full 最终合法重量/换型为 2360.12/179，None 无合法结果，详见 `outputs/iz300b/large300_newskill_final_audited.md` 与合同测试台账。

直接试验确认的改善是 Full 第二轮修复了插入空档逻辑，取得完整合法解：第二轮 solver 第 145 行起重写 `compute_start`，第 178 行前驱检查、第 199 行后继检查均进入正常构造路径。相对首轮只新增 `safe_setup` 并重写该函数，其余构造、Q-time、校验和输出逻辑未变。本例 43 个批均为单件批。Q-time 上界仍仅在最后校验，没有上游回推、快照恢复或 DFS，不能将合法结果归因于尚未实现的机制。

同时暴露两个尚未修复的执行缺口：

1. **参考资料未被实际读取。** Full 五次 Worker 均授权并成功加载新 Skill 主文件，投递测试也确认全部六份 references 存在且允许读取，但五份事件文件均无这些参考文件的成功读取记录，bash 调用也无相关路径引用。因此这次不能视为完整验证了参考文件中的构造/回修方案。后续应验证如何在任务书与读取预算中确保关键参考内容被消费，不能只重复增加 Skill 名称。
2. **生成优化函数未接到入口。** 第三轮局部 lane 的 solver 第 577 行定义 `coupled_local_search`，第 759 行 `main()` 仍直接构造、校验和输出，没有调用该函数。评测合法持平，但局部移动、路线切换和有效合批激活门禁均失败，候选不晋升。构造 lane 超时无修改；群体 lane 在第 428 行把列表型 `batch_family` 放入集合导致运行异常。平台正确保留第二轮合法 incumbent，但本轮优化没有产生有效提升。

这些结论支持优先补齐“参考内容进入编码上下文”和“算法机制进入真实执行路径”的闭环；尚未实施相关预算/编排修改。本批只做直接接入试验，不能据单例宣称新 Skill 有稳定净收益，也不能把未读取参考内容的结果当作其算法设计已被证伪。
