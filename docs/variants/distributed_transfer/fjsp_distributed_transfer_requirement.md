# 分布式可转移 FJSP 自演进演示需求文档

## 1. 问题目标

给定 Distributed Flexible Job-Shop Scheduling Problem with Transfers
（分布式可转移 FJSP，DFJSPT）算例，生成一个完整合法调度方案，使所有工件的所有工序都被分配到各工厂的机器上，并尽量最小化最大完工时间（makespan）。

分布式可转移 FJSP 与标准 FJSP 的关键差异是：
- 存在**多个地理分布的工厂**，每个工厂拥有一组独立的机器。
- 同一工件的不同工序**可以分配到不同工厂**（允许跨厂转移），但会产生转移时间成本。
- 同一工厂内的机器间转移也有时间成本（通常小于跨厂转移）。
- 求解器需要同时处理**工厂分配、机器分配、工序排序**三个子问题。

本变种算例的主体格式与标准 FJSP 不同：每道工序的候选机器不仅包含机器编号和加工时间，还包含**工厂编号**以及**单位能耗**——因为这是一个多目标优化问题（makespan + 最大工厂负载 + 总能耗）。DFM 文件使用全局 1-based `machine_id`，但不能根据机器数值推断所属工厂；候选组开头的显式 `factory_id` 才是权威。输出时两个编号分别减一，资源身份始终是完整的 `(factory_id, machine_id)`。

算例的元数据头部（前 5 行）声明了工件数、工厂数、每工厂最大机器数及每工序每工厂可选机器数范围。

## 2. 硬约束

- 每个工件由若干道工序组成，同一工件内部必须满足工序先后顺序。
- 每道工序必须分配到一个工厂，并从该工厂的候选机器集合中选择一台机器加工。
- 工序的加工时间等于所选机器在该工厂对应的 processing time。
- 同一台机器（同一工厂内）一次只能处理一个工序加工活动，机器上的加工区间不能重叠。
- 若前后两道工序分配在不同工厂，则需要增加跨厂转移时间（`T_F`）；若在同一工厂但不同机器，则需要增加同厂转移时间（`T_M`）。
- 转移时间必须在解的时间传播中体现——工序的开始时间 = max(前驱工序完成时间 + 转移时间, 所选机器的空闲时间)。
- 转移类型必须先比较工厂再比较机器：工厂不同始终使用 `T_F`，即使两个全局机器编号数值相同；只有工厂和机器都相同才是零转移。
- 同一 `(factory_id, machine_id)` 可能对应多个加工时间/能耗候选，必须保留全部元组并按实际加工时长消歧，不能用二元键覆盖。
- 解必须包含所有工序，不能遗漏或重复。

## 3. 优化目标

主要目标是最小化 makespan。辅助观察指标包括：

- `max_factory_workload`：各工厂的总加工时间（负载）的最大值。
- `total_energy_consumption`：加工能耗 + 转移能耗之和。
- `priority_completion_time`：优先级工件的最大完工时间。
- `runtime_seconds`：候选求解器运行时间。

只有 evaluator 判定合法的解才能参与质量比较。非法解不能因为 makespan 较小而被接受。

## 4. 自演进要求

系统应从本需求文档、IO 文档和分布式可转移 FJSP 算例出发，执行固定 evaluator 支撑的自演进循环：

1. 解析 DFJSPT 输入——读元数据头部（工件数、工厂数、每工厂机器数范围）+ 每工件的工序候选数据（含工厂编号、机器编号、加工时间、能耗）。
2. 对每个工序：确定工厂分配 + 机器分配 + 排序。
3. 时间传播中计算跨厂/同厂转移时间，加到工序开始时间中。
4. evaluator 检查工序覆盖、机器容量、工序顺序、候选机器合法性、转移时间是否正确计入。
5. 汇总 makespan、最大工厂负载、总能耗、合法率和失败原因。
6. 后续代码演进应优先修改工厂分配策略和转移时间感知的插入/解码逻辑。

Evaluator 是唯一合法性和质量判定来源，模型自评不能替代 evaluator。
求解器内部自检若返回非空错误列表，也必须丢弃该候选，不能将其当作合法 incumbent 输出。

本变种算例来源于公开的 DFJSPT 基准数据集（DFM01~40），由 Hurink 标准 FJSP 基准通过添加工厂维度、机器独立编号、能耗数据和转移时间得到。
