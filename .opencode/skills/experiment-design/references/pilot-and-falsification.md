# Pilot 与反证

## 先定义 pilot 的唯一问题

让一次 diagnostic smoke 只回答一个会改变下一步的问题：机制是否进入预期路径、输出是否仍合法、搜索覆盖是否达到声明规模、资源是否存在数量级风险，或是否值得支付一次完整 Core evaluation。

缩小实例、预算、迭代或重复次数时，必须保持相同目标、约束、核心代码路径，并能触发假设针对的结构。若缩小后不再触发瓶颈，它只能检查正确性和插桩，不能支持性能结论。

## 预先写反证条件

- 破坏解析、CLI、JSON、完整解码或合法性。
- activation checks 显示关键机制未执行或覆盖远低于声明。
- 成本转移到其他阶段，主预算内没有改善空间。
- 收益来自跳过工作、缓存预热、输入顺序或评测口径漂移。
- 实现代价超过剩余预算能验证的范围。

触发后回退、缩小假设或补诊断。不要更换幸运 seed、实例或指标来挽救路线。

至少保留实际命令、输入和预算差异、返回码、合法性、关键 telemetry、异常与候选工作区状态。合理结论包括“值得进入 Core”“机制未激活”“正确但成本过高”和“证据不足”；diagnostic smoke 不得声称已经提升 incumbent。
