## 1. 选择正确表示

用两个耦合决策表示一个解：

- `assignment`：为每道工序选择一个机器-加工时间选项。
- `sequence`：确定每台机器上已分配工序的顺序。

把两者解码为最早可行开始时间。解码应尽量确定性，并立即拒绝环或非法分配。每个邻域要么返回完整可行解，要么不返回候选。

将 incumbent 与当前搜索状态分开保存。探索更差或结构更远的入口时，不能丢失当前最佳可行解。

## 2. 构造有效多样性

使用少量互补规则，而不是大量同一规则的微调版本：

- 最早完成和 active schedule 规则。
- 剩余工作量和关键负载压力。
- 机器负载平衡。
- 空闲时间和作业等待压力。
- 基于候选特征的通用线性评分。
- 反向或尾部构造。
- 有界 beam search 和 lookahead。

用 assignment/order 指纹衡量多样性，而不是只看 makespan。列表对象不同不代表解码后的 CP 入口不同。

拟合分数只能使用工序、负载、松弛、加工时间和剩余工作等通用特征。不要加入实例身份或已知目标值。

## 3. 有选择地使用前瞻

当局部最优 dispatch 选择可能制造延迟拥塞时，才投入前瞻：

1. 保留少量当前候选工序。
2. 模拟一到数步未来决策。
3. 比较预计完成时间、机器负载、空闲、剩余工作和关键压力。
4. 在有界分支中选择当前动作。

分支宽度要小。宽前瞻可能耗尽预算，却仍反复进入同一盆地，尤其是在大型低柔性实例上。

## 4. 提取关键路径邻域

无需复制完整 tabu search，也可以复用 N8/NK 类邻域的可迁移部分：

- 定位关键机器块和近关键工序。
- 生成相邻交换、边界插入、短距离移动和短块重排。
- 将关键的柔性工序改派到可信替代机器。
- 按重新解码后的 makespan、负载变化、关键块结构和指纹距离评估。
- 保留有界且结构不同的入口，而不是无限延长 tabu 轨迹。

限制候选数、轮数、已见状态、退化步数、移动距离和墙钟时间。这个阶段的目的通常是给后续求解器创建更好的入口。

## 5. 按柔性匹配策略

### 低柔性且加工时间无跨度

分配变化不能降低单工序加工时间，优先优化机器顺序：

- 关键块交换和插入。
- 多个精英解之间的共识窗口重排。
- 有界顺序重建。
- 结构不同的构造基解。

注意一条超长关键块吞噬大部分关键路径的情况。许多表面不同的入口可能在改进后回到同一吸引子。

### 低柔性但存在加工时间跨度

联合改进 assignment 与 sequence：

- 在关键或过载工序附近建立小型 assignment trust region。
- 生成 N8/NK 类顺序候选。
- 用短 relaxed CP 探测入口响应。
- 对最有响应的入口运行较长最终改进。

不要简单惩罚非最短加工时间选项。较慢机器仍可能通过缓解瓶颈降低整体 makespan。

### 中等柔性

在分配多样性和顺序质量之间平衡。综合负载统计、关键柔性工序、指纹距离和 makespan gap 排序，使用有界前瞻及 assignment-aware 邻域。

### 高柔性

把更多搜索预算用于 assignment 多样性和瓶颈平衡。只做 sequence 邻域会浪费主要搜索空间。构造负载均衡分配后，再使用 tail CP 或完整 CP。

## 6. 分层使用 CP-SAT

逐步增加 CP 成本：

1. 固定 assignment 的 sequence 修复。
2. 只允许选定工序改变 assignment。
3. 短时间 relaxed response probe。
4. 完整最终改进。

assignment trust region 可从关键块附近、过载机器上或具有竞争性替代机器的工序中选点，并显式限制改变数量。

为一个主要最终入口预留最大的连续时间片。若还有预算，对一个真正不同的入口做较短尝试，通常比许多中等时长尝试更有效。

## 7. 按可修复性选择入口

最终集合始终包含 incumbent。其他入口至少提供一种价值：

- 更好的探测后质量。
- 有效探测增益，且探测后结果接近 incumbent。
- 有意义的 assignment/order 距离。
- 不同但可信的关键块结构。
- 更好的负载平衡，同时 raw makespan 没有过大差距。

不要只按 probe gain 排序。可以优先比较：

```text
post_probe_gap_bucket,
raw_gap_bucket,
critical_block_penalty,
load_penalty,
-probe_gain,
-fingerprint_distance
```

很差的 raw entry 只有在短探测后接近 incumbent、且结构显示另一个可修复盆地时，才值得占用主要最终入口。

## 8. 分配时间预算

使用一个绝对 deadline，并在启动任何早期阶段前预留返回可行解和最终改进的时间。

长求解的初始参考比例可以是：

- 25%-35%：构造和基解生成。
- 15%-25%：有界入口探索。
- 5%-12%：短探测。
- 35%-50%：最终 CP 或精确改进。

这些比例不是 AlgoForge 的固定流程。应按实例结构、项目现状和正式 timeout 自主调整；入口不再改善 incumbent 或结构多样性时及时停止。

## 9. 识别搜索坍缩

以下信号说明候选池可能已经坍缩：

- 多个指纹最终得到相同 makespan 和关键结构。
- 当前入口由一个关键块支配，探测后原样返回。
- 新构造的 raw makespan 不同，但最终收敛到同一瓶颈。
- 入口生成消耗明显时间，却没有提高质量或可修复性。

此时应改变构造盆地或邻域类型。继续给同一组坍缩入口增加最终时间通常无效。

## 10. 映射到 Harness 研究事实

- Worker 的短 smoke 是探索证据，写入 attempt 摘要，不直接更新 incumbent。
- Main Agent 用一个有界 `WorkerAssignment` 固定方向、方法包、交付物和 lineage；同轮修补不得换方向。
- 正式结果与局部结果冲突时，以 Core evaluator 为比较事实，并调查环境、随机性或修改范围。
- 同一策略只改变常数、seed 或运行顺序时，先检查是否实质重复；换到新 incumbent 或新结构假设时可以重新探索。
- promotion 理由必须引用候选自己的合法性、makespan 和语义审查证据；不得用 Baseline 或其他候选的结果替代。
