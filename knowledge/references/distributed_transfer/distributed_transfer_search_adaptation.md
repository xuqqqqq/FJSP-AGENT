# 带转运的分布式 FJSP 搜索适配

## 表示与解码

给定的 Luo 等人文献采用三个耦合向量：工序顺序（OS）、工厂分配（FA）和机器分配（MA）。仓库中的求解器可以使用其他表示，但必须保留这三类决策并联合解码。工厂或机器的变化可能同时改变加工时间、转运延迟、工厂负载、能耗和机器序列可行性；不得只修改一个缓存项就对这类移动评分。

维护一个独立且经过完整解码的当前最优解。比较候选解时，必须完整重算包含转运时间的工件就绪时间和 `(factory,machine)` 资源容量。应保留结构不同的 FA/MA 分配，因为具有较低最大完工时间的不同吸引域，其负载和能耗可能存在显著差异。

## 初始化

文献中的 GLR 种群混合全局、局部和随机分配选择。其报告的实现采用 60/30/10 比例，但这些比例只是初始假设，不是仓库常量。应保留以下机制：

- 全局种子在分配工序时持续更新工厂和机器负载；
- 局部种子在单个工件或有界子集内产生多样化决策；
- 随机种子用于保持分配多样性，但仍必须通过合法解码器；
- 至少包含一个转运感知贪心种子，联合比较加工完成时间、前驱转运时间和工厂负载压力。

对于单解构造通道，使用有界多起点规则模拟 GLR 中有用的部分，不得把一次贪心派工作为模因算法。

## 变异与局部搜索

群体搜索是文献针对这些 DFM 实例支持的主要机制。采用保持前驱约束的 OS 交叉、保证候选选项合法的 FA/MA 交叉或变异、结构重复控制以及有界局部改进。文献提出在短 OS 片段上使用逆序变异（ISM），并在 MA 位置上使用机器替换变异（RMM）。

其关键路径局部搜索包含三个互补机制：

- `LSO_SP`：在保持工件前驱关系的前提下，交换或重定位关键块附近的工序；
- `LSO_MPT`：把关键工序移动到加工时间更短的合法工厂-机器选项；
- `LSO_RTT`：选择能够降低前驱/后继转运代价的合法选项。

仓库实现必须通过完整解码器评价这些移动。在所选方法族允许时，还应加入同厂换机、跨厂迁移、避免重复支付转运代价的成对移动，以及负载均衡移动。

## 目标契约

文献使用非支配排序和拥挤距离维护帕累托种群。当前固定 Core 则有意按最大完工时间、最大工厂负载、总能耗的顺序进行词典序选择。Worker 可以在内部维护帕累托档案以保持多样性，但必须按照固定词典序契约输出一个合法解。不得把该顺序替换为加权和，也不得宣称平台复现了文献中的帕累托评价协议。

精确修复仍是可选机制。如使用精确修复，应将其限制在有界关键工序集合或规模可控的完整模型内，报告求解器实际运行证据，并在超时时保留启发式当前最优解。

## 短预算的实现顺序

先检查表示与解码的能力上限。只在机器末尾追加工序会留下可利用的空闲间隙，
此时扩展分配邻域仍可能被同一个低质量解码器限制。维护每个完整资源的有序占用区间，
从工件前驱完工加转运等待开始寻找可容纳加工时长的最早间隙；插入后更新区间并
完整解码受影响的后续工序。不得把旧开始时刻与新分配拼接成未验证的候选。
这是可检验的解码假设而非所有实例的强制算法；有空洞证据时优先与追加解码比较。
2026-09-16 v5 对照组 DFM33 的间隙插入候选曾改善目标，但单次收益不能当作通用保证。
构造、局部与群体可以共享可行解码器，候选生成和搜索控制仍需保持各方法族的区别。

已合法的解析器和 incumbent 不是重写目标。先保留完整fallback，接入一个非原分配或不同顺序
的可达候选生成器，完整解码、重算三目标并验证输出，再扩展VND、种群或精确修复。
解析、候选身份、解码、目标接受和搜索桥接组成首次搜索的必需闭包；仅下发parser无法完成
转运搜索验收。短Worker预算下，优先把第一个有效候选闭环写完，而不是一次性实现完整论文算法。

## 单点与工序段邻域

LSO_MPT用于筛选更快加工候选，不意味着更快机器一定更好。替换候选后同时检查前驱、后继
转运边界以及目的资源拥堵。LSO_RTT筛选较低边界转运的候选，但最终仍按makespan优先排序。
将连续工序段迁移到同一工厂能减少反复跨厂；若该厂拥堵，则允许把段分流到其他厂。
对长度受预算控制的工序段，可用动态规划或束搜索枚举eligible元组：状态保留末尾资源、累计
加工与转运估计、工厂/机器压力。该估计只筛选候选，不能替代完整解码后的Core目标。
普通机器序列采用空闲间隙插入或完整资源弧重解码，禁止对旧开始时间局部加减后直接接受。

## 不同方法族的差异与证据

构造通道比较转运感知派工、同厂段聚集与负载分流的有界多起点；局部通道在当前解上执行
单点/工序段分配和关键块顺序邻域；模因通道必须维护不同FA/MA结构，生成合法后代、替换并
做局部改进。三条lane不能只是同一贪心函数的不同随机种子。
精确通道按规模与预算选择：300道工序、多个工厂和大量候选时，不默认要求完整三阶段CP；
可对关键资源和短工序段做有边界的CP修复，固定其余资源序列并正确处理跨邻域的前后继转运。
未真实到达Solve不能声明精确方法生效。

报告真实评价的分配选项数、完整解码次数、同厂/跨厂/工序段移动及接受数，以及最终转运弧数。
存在搜索但没有改善与根本没执行搜索必须区分。后者应先修可达性和机制，而不是仅调种群规模。

## 实验反馈与修订原则

长编码预算试验进一步说明：仅补旧局部搜索的计数未改变目标；三起点构造也没有收益。
因此基础语义闭包是可行性条件，不是每轮重新实现的工作清单。正式优化任务必须绑定
现有源码中的一个具体限制，说明新增候选、解码或搜索控制如何改变旧行为。
把所有理论算子同时列为必做项会挤占接入与验证，应选择一个最小完整机制逐步演进。
随机种子与方案对象接口混淆曾导致种群初始化立即失败；盲目int转换不能修复这种语义错误。
合法fallback与方法激活分开审计，运行错误应利用授权复验预算修复，不能当作邻域无收益。

2026-09-16 的三组配对实验，在同一合法历史 starter、三轮和相同算法时间预算下，
None/Full 的 makespan 分别为 DFM31 的 866/1383、DFM32 的 1454/1414、
DFM33 的 1370/1370。它们是固定词典序协议下的单次实验，不是论文结论，
不能据此按算例名选择算法，也不能把其中的目标值作为生成代码的输入。
这批结果只说明合法性适配已可用，领域增强的质量收益尚不稳定。

DFM31 的正式初始 Worker 均超时；事件中出现 Skill 工具的 ripgrep 执行错误，
并有重复加载后改为直接读取的行为。应按任务书的镜像路径直接读取 Skill，
把加载失败与模型延迟、代码未落盘分别记录。工具错误不能归因为邻域无效。
DFM32 最终代码报告约两万三千次完整解码但仅两代群体演进；这不是充分探索的证明，
需要检查解码耗时、重复结构比例和每类移动的候选质量，避免穷举低价值替换耗尽预算。
DFM33 未晋升也不能仅凭最终 incumbent 的诊断缺失断言全部候选没有搜索，
应检查各 lane 的执行输出、激活检查与拒绝理由。

建议复盘顺序：

1. 核对加载、首次落盘、编译、smoke 是否完成；失败先修执行路径。
2. 核对 CLI 实际进入机制，计数只记录真实生成与完整解码；不得伪造激活。
3. 核对新机制保留完整 incumbent 和原有效搜索，合法但退化不能覆盖当前最优解。
4. 对真实停滞按关键路径/资源拥堵筛选候选，并尝试单点、工序段及顺序的互补邻域。
5. 在获准方法族内使用 Tabu、ILS 或多样性保留跳出吸引域；探索解与输出 incumbent 分离。

上述筛选只降低候选枚举成本，最终接受仍完整重解码并按固定目标比较。
复测必须保留配对预算及版本指纹，不用修订后的结果替换旧版本的失败记录。

## 文献来源

主要给定文献：Luo 等，*An efficient memetic algorithm for distributed flexible job shop scheduling problem with transfers*（2020）。其中的 DFM 表示、GLR 初始化、OS/FA/MA 编码、ISM/RMM 变异和 `LSO_SP`/`LSO_MPT`/`LSO_RTT` 邻域构成上述机制的依据。仓库固定的 IO 和 evaluator 仍是标识符、常量与晋升顺序的权威来源。
