# 解码器与邻域指引

本参考用于自主生成的 FJSP-SDST 求解器，以及其他必须把排序移动重新解码为完整可行排程的变体。

## 解码器职责

解码器负责把一种表示映射为带时间的已排程工序。对 SDST，稳健的表示通常是：

- `assignment[(job_id, op_id)] = machine_id`
- `machine_sequences[machine_id] = [(job_id, op_id), ...]`

解码器必须从头重建 `start`/`end` 时间：

- 一道工序只能在其作业内前驱结束后开始。
- 若存在 setup，一道工序只能在同机前驱结束并加上换型时间后开始。
- 解码后的排程必须恰好包含每道工序一次。
- 发生死锁、环、漏工序、重复工序或机器分配不合资格时，该候选即为不可行，必须跳过。

对 SDST，setup 是机器上的排序效应。除非任务契约另有说明，减少总 setup time 只能作为次级判定或诊断信号，主要目标仍是 makespan。

## 局部邻域规则

优先使用“修改完整表示后再解码”的邻域：

- 围绕关键工序或完工较晚工序的同机相邻交换；
- 在小窗口内做有界的同机插入或重定位；
- 对当前机器成为瓶颈的工序做替代机器重分配，再插入目标机器的有界窗口；
- 删除少量工序后，用同一解码器做小规模 destroy-repair 重插。

第一版避免做宽泛的 all-pairs 扫描，这类扫描通常在还没学到有效信息前就先超时。

## 候选移动过滤

在评价移动之前：

- 先检查被移动工序是否仍保留 eligible machine；
- 若解码器无法证明可行性，避免把工序移到其作业内前驱之前；
- 优先关注关键路径、最晚完工机器或瓶颈机器上的工序；
- 对每轮的候选位置或采样移动数设置上界。

在解码之后：

- 比较解码后的 makespan 与当前最佳值；
- 没有改进时保留 incumbent；
- 只有观察到 undo loop 时才保留小型 move memory；
- 除非方法明确实现了有界随机搜索且仍满足运行时约束，否则不要接受更差的排程。

## 常见失效模式

在耗费 evaluator 时间前，先拒绝或修补这些模式：

- 局部搜索返回部分排程，而调用方仍然接受；
- 解码失败返回 `[]`、`None` 或 makespan `0`；
- `machine_sequences` 保存的是 `(job, op)` 对，但辅助代码把条目当成字典；
- 辅助代码在交换或插入工序时不检查机器资格；
- insertion、VNS 或 SA 循环对所有工序和所有位置做无界扫描，没有迭代或时间上限；
- 独立求解器运行时的辅助文件导入 `harness_agent`；
- 顶层 helper 被错误插进 `main()` 或其他函数内部；
- 修补时直接替换已 promotion 的构造骨架，而不是围绕它做补丁。

## 返回方案前的自检

worker 应能对下列问题全部回答“是”：

- 求解器是否只解析活动 IO 契约，而不是其他假定格式？
- 输出中是否每道工序都恰好出现一次？
- 机器 ID 的内部表示与输出 ID 是否都符合 evaluator 预期？
- 每道工序是否都使用了合资格机器与正确加工时长？
- 每道工序是否都满足 job precedence？
- 每台机器的序列是否都满足 non-overlap 与 setup time？
- 任一邻居不可行时，局部搜索是否保留 incumbent？
- 是否存在明确的迭代或时间上限？
- 本次改动是否只是围绕已 promotion incumbent 的单一规则或算子变异？
