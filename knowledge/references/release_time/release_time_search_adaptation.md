# 释放时间 FJSP 搜索适配

释放时间会使早期机器容量分布不均。有效的构造优先级应把工序关键性、释放松弛量和候选机器可用时间结合起来。多个起点应在已释放工件之间采用不同的平局规则，但不得调度尚未释放的工件。

局部搜索、禁忌搜索或模因搜索仍以分配/顺序作为移动状态，并使用释放时间下界进行完整重新解码。优先考虑以下移动：填补未来释放时间之前无法避免的空闲间隙、缓解晚释放工件形成的瓶颈，或把工序移离初始可用时间较晚的机器。增量变化量只能用于筛选；接受候选前必须完成一次完整合法性检查。

在精确混合方法中，释放时间下界是代价较低的约束，可加入完整模型或信赖域模型。启发式方法仍适合生成当前最优解；CP-SAT 是可选机制，而非默认方法。进入 exact lane 时，应先保留并验证启发式 incumbent，再把它作为 CP-SAT hint；正式 CLI 运行中的 exact 阶段应消费扣除解析、构造和输出余量后的主要剩余预算，并用绝对 deadline 截止。WorkerAssignment 中不超过 3 秒的 smoke 上限只约束 Worker 自测，不能被硬编码为正式求解的 `2.5` 或 `3` 秒上限。若完整模型规模过大，应缩小释放变量或切换局部信赖域，而不是把 60 秒等正式候选预算静默截短为 smoke 预算。

## 研究依据

给定语料包含面向带工件释放日期动态 FJSP 的 GEP 反应式策略和 MCTS 研究。本卡片只复用其中的释放感知优先级与搜索思路；平台契约是给定的静态释放时间问题，因此不引入在线到达或重调度语义。
