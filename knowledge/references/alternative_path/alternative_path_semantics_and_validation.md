# 可选工艺路线 FJSP 语义与验证

当前契约是标准 FJSP 的有界路线选择变种。每个工件有一条 `route_id = 0` 的原始路线，以及标准主体之后解析出的零条或多条尾部路线。每条路线都是从该工件原始工序池中选出的 0 基 `op_id` 有序序列。求解器必须为每个工件恰好选择一条路线，并且只调度该序列中的工序。

该契约不支持任意路线图、部分路线合并、同一路线内重复工序，或同一工件同时执行多条路线。尾部路线是原始路线的替代项，不是追加在原始路线后的额外工作。

## 解析层不变量

- 工件 `j` 的原始路线是规范序列 `0, 1, ..., original_op_count-1`。
- 尾部为每个工件声明 `K` 条替代路线，因此路线 ID 范围为 `0..K`。
- 每条替代路线先给出自身工序数，再给出对应数量的 `op_id`。
- 列出的每个 `op_id` 必须是该工件原始工序池中的合法 0 基工序。
- 路线可以重新排序或跳过原始工序池中的工序，但同一路线内不得重复工序 ID。
- 同一工件的尾部路线不得与原始路线或其他尾部路线重复。
- 不允许存在多余路线词元；解析器必须消费完整尾部。

## 输出层不变量

- 解文档必须包含 `selected_routes`。
- 每个工件都必须存在 `selected_routes[job_id]`，且值指向范围内的路线 ID。
- 调度必须为所选路线上的每道工序提供一条记录，且不得包含路线外工序。
- 对所选序列 `(a, b, c, ...)`，即使它与原始路线顺序不同，也必须按该精确顺序检查前驱约束。
- 候选机器合法性、加工时长和机器不重叠规则与标准 FJSP 相同。

## 运行影响

验证是动态的：预期工序集合取决于 `selected_routes`。因此，调度可能以两种不同方式非法：

- 遗漏所选路线中的工序。
- 包含属于工件原始工序池、但不属于所选路线的工序。

因此，路线选择、解码与输出写入必须保持耦合。改变 `selected_routes` 却不重建调度，会产生陈旧工序覆盖；改变调度却不更新 `selected_routes`，会产生路线/覆盖不匹配。

evaluator 是该语义的权威来源。它从 `selected_routes` 重建每个工件的所选序列，按这些序列检查工序覆盖，再应用路线顺序前驱约束和普通机器/资源验证。不得根据一般替代路线文献推断更广泛的语义。
