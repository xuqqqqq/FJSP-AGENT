# AWLS/HGTSA 行为契约

Coding Agent 与语义审查者应验证行为是否真正成立，而不是只看名称。

## 解码器

- 若 `machine sequence` 中某道工序的作业前驱尚未完成，则该工序必须等待；按机器主序直接回放是无效的。
- 如果完整扫描一轮后仍有未调度工序，且本轮没有任何工序被成功调度，则解码必须失败，且不得替换 `incumbent`。
- 每个被接受的已解码状态，都必须在合法机器上以选定加工时长恰好包含每一道必需工序一次。

## 关键图与关键块

- 关键性必须从当前已解码析取图上的前向与后向时序传播推导出来。
- 关键机器块必须是由紧致 `machine arc` 连接的连续工序序列。仅仅挑选最忙机器上的工序，不能算关键块邻域。

## 邻域

- 同机移动必须修改显式机器顺序，并在比较前完成解码。
- 异机移动必须先把工序从旧顺序中移除，再插入合法目标顺序，然后对完整状态进行解码。
- `K-insertion` 必须评估超过相邻交换的结构，并且只保留完整合法的候选。
- 移动应用必须具备事务性。每个候选都应在克隆体或快照上执行，重建 `links/times`，并且仅在解码成功后提交。若出现异常、成环、部分解码或超时，`current` 与 `best` 都必须保持不变；先修改 `current` 再在出错后捕获异常是不合格的。
- 任何沿机器前驱/后继链接的遍历，都必须使用 `visited set` 或工序数量上界，以防受损候选导致无界路径或无界 `tabu key`。

## 禁忌与特赦

- 接受移动后存入的 `tabu` 属性，必须描述能把状态恢复到前一状态的逆向移动。
- 对换机重分配而言，逆向属性使用旧机器与旧插入上下文，而不是新机器顺序。
- `tabu` 候选只有通过面向全局最优目标的显式 `aspiration` 规则，才可以被接受。
- 当前状态与全局最优状态必须是不同对象，或不可变快照。

## 自适应搜索与多样化

- 权重或 `zi` 的更新必须能够实际影响可达移动的打分或选择。
- 搜索停滞时必须触发有界多样化机制，例如加权扰动、重启或受控随机化。
- 多样化必须保留全局最优，并保持随机种子可复现性。

## 运行时

- 生成的 CLI 必须接受 `--time-limit-sec`；Core 传入的数值会略小于其进程超时，以便为序列化与进程退出预留空间。
- 求解器必须在构造、候选生成、搜索、验证、序列化以及所有组合分支上共用同一个截止时间。
- 截止时间检查必须出现在嵌套的 `operation/machine/insertion-position` 循环内部，而不只是放在重启或外层 `tabu iteration` 之间。单次邻域扫描必须可中断。
- 候选物化必须使用显式 `shortlist/window/cap` 做边界控制。不要在检查截止时间之前先构建无界的 `all-pairs` 移动列表。
- Worker 侧验证仅限编译，以及一次固定随机种子、最长 3 秒的短烟雾测试。不要重试失败的 worker 烟雾测试，也不要用临时内联搜索循环替代它。多随机种子与正式基准运行属于 Core 的职责。
