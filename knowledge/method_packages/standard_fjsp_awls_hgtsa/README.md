# 标准 FJSP AWLS/HGTSA 方法包

## 目的

该方法包提供与具体实例无关的实现参考，用于依据当前激活的需求与 IO 契约生成标准 FJSP 求解器。它提供的是方法知识，不是预先求好的排程，也不是后端编排代码。

## 适用性与检索阶段

该方法包属于第二阶段实现候选，而不是第一阶段默认方案。只有在 Main Agent 已判断当前标准 FJSP 方向主要由工序分配/机器顺序耦合改进、关键路径局部搜索、禁忌搜索或自适应多样化主导时，它才应进入可见范围。

该方法包是建议性的方法知识，不是规定性的实现方案。当实例、当前 `incumbent` 与预算支持一条连贯的 AWLS/HGTSA 路线时，Main Agent 可以选择整个包；也可以只取其中个别资产，作为更小规模或混合方向的参考。建议分阶段推进，并不意味着禁止直接选择完整方法。

当合法 `incumbent` 或完整基线状态能够表示为工序分配加显式机器顺序，且可用预算足以支持反复执行“解码并评估移动”时，应优先考虑本包。不要仅因为它是知识库里最详细的资产就选择它。

当当前任务只是构造一个最小合法基线、所选方向是 CP-SAT/精确模型，或当前激活的变种已经使标准解码器与移动语义失效时，不应优先选择本包。

Coding Agent 应基于本包进行推理，并针对当前求解器 CLI、状态表示、实例特征和输出模式独立适配、组合、简化或重写其中思路。参考来源只是可选学习材料，不是必须照抄的答案。如果 Agent 宣称采用了完整方法包，那么最终行为必须保留其连贯、可执行的搜索语义；这种保真要求并不等于复制源码。它也不得复制基准特定的分数、排程、机器顺序或目标值。

## 必需结构

1. 从当前输入中解析每个作业、每道工序、每台候选机器及其加工时长。
2. 构建一个合法的构造状态，包含工序分配与显式机器顺序。
3. 使用作业优先约束与机器优先约束传播来解码状态。部分状态或死锁状态都属于不可行状态，不能替换 `incumbent`。
4. 从解码后的排程中提取精确关键路径与紧致关键机器块。
5. 生成有界的同机关键块移动，以及异机重分配/插入移动。
6. 对逆向移动使用 `tabu` 属性，对全局最优启用 `aspiration`，并维护相互独立的当前状态与全局最优状态。
7. 只有在移动被接受后，才更新工序权重或等价搜索压力；搜索停滞时要保留显式多样化机制。
8. 每个候选都必须先解码并验证，再比较目标值。
9. 超时或解码失败时，必须保留当前最好的完整合法排程。

## 资产

- `reference_solver.py`：完整 Python 方法参考。生成的求解器可以学习、适配、组合、简化或替换其中结构和函数，但仍必须遵守当前激活的 IO 与 evaluator 契约。既不要求，也不建议直接移植源码。
- `behavior_contract.md`：用于区分“真实方法实现”和“只有函数名或注释”的行为检查。
- `standard_fjsp_algorithm_semantic_review_contract.md`：独立 reviewer 在晋升阶段使用的方法语义契约。

## 适配边界

参考实现可能会为了其历史 CLI 使用仓库内的 `parser/solution helper`。独立的 `agent-generated solver` 必须用当前 solver contract 允许的代码替换这些导入。算法结构属于本方法包；`parser/evaluator` 的权威来源仍然是当前激活的 IO 文档与 Core evaluator。
