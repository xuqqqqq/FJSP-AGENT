# 独立工业 FJSP 求解器生成

使用者只有需求、IO、输入和固定评价器。输出独立源码、运行入口、微型测试、完整调度及评价器报告；本 Skill 不携带初始 solver。不得导入、调用、复制来源项目的 solver、preset、tuner 或历史排程。不迁移任务 ID 排序、机器偏置或调好的常数。

目标固定为 `max (W_H, -N_setup)` 的严格词典序：`W_H` 是绝对时间 `H` 之前（含边界）完成的成品重量；`N_setup` 是评价器定义的机器序列在**全排程**中的正换型次数。所有任务选择一条完整路线，所有工序必须输出，包括 H 之后的工序。有限批容量、精确族匹配和 Q-time 均为硬约束。

## Harness 接入边界

本项目中仅在工业 WorkerAssignment 明确授权时使用本 Skill。活动需求、IO、Main 选定方法、文件权限、命令和预算优先；本文方法不新增 lane 或免费修复轮。普通机/批机分类、容量转换、日历边界及时间精度均按当前 IO 实现。

参考伪代码中的 `fixed_evaluator`、`export_reload_and_fixed_validate` 表示完整工作流的正式评价步骤，只由 Harness Core 执行；Worker 及生成求解器不得读取、导入或调用外部评价器。求解器内部实现独立完整自检，提交后使用 Core 反馈修订。微型例子的执行服从任务书允许的检查和预算，不额外调用评价器或运行旧项目脚本。

## 工作导航

1. 阅读 [来源与适用边界](references/sources.md)：先分清源码已实现、历史验证通过、新实现必须补齐的内容。来源文件只供溯源，运行本 Skill 不需要访问它们。
2. 建模前读 [解析与状态](references/parsing-state.md)，从当前四份输入材料冻结字段、时间、容量、换型和评价口径。已有固定评价器不修改；补充检查不得替代它。
3. 写首个构造器时连读 [合法构造](references/feasible-construction.md) 与 [冲突回修](references/conflict-repair.md)。实现候选安置、快照恢复和有界搜索后，才运行完整算例。
4. 按 [微型验证](references/micro-validation.md) 检查正反例。不要以“输出了文件”或“部分任务合法”代替完整合法性。
5. 获得固定评价器通过的完整解后，按 [质量优化](references/optimization.md) 一类一类加入启发式。始终保留不可变的最佳完整合法解。

文内标签：**[实装]** 表示读到可执行实现；**[历史验证]** 表示有指定口径的结果证据，不是对任意输入的保证；**[补齐设计]** 表示从约束推导的独立实现方案，尚无该方案在工业全量算例上的验证。不要将补齐设计描述为旧算法已有功能。

## 完成条件

先通过微型正反例、状态恢复不变量，再完整导出并重读结果，使用固定评价器检查全部任务/路线/工序及指标。若搜索预算耗尽且无完整合法解，报告“预算内未找到”及最小已知冲突；不得放松约束、删任务、伪称不可行或把部分排程作为成功交付。有合法 incumbent 时，优化失败返回该解。
