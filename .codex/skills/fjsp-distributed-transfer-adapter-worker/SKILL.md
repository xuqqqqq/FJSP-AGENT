# 带转移时间的分布式 FJSP 适配器

## 短预算入口

本文件已读后不重复调用 Skill 工具。其他已授权 Skill 可直接读取任务书中
`sandbox_path/SKILL.md`；工具报错后按该路径读取，不重试发现、不扩大目录搜索。
已有合法解析器时，只核对当前修改涉及的语义，不重新实现下面的解析步骤。
先定位现有解码、候选生成和 incumbent 接受入口；说明一个具体限制和拟改函数，保存可运行的算法补丁并执行
获准 smoke；再在剩余预算内扩展算法。优先阅读搜索卡与本轮修改相关的小节，
不为复现完整论文而先读完所有可选材料。计数增加不等于求解质量提升。

## 契约

- 解析五行 DFM 头部和分组候选；输入标识为 1-based，输出标识为 0-based。机器 ID 在跨工厂分组转换后仍保持全局编号，不得在各工厂内重新编号。
- 转移延迟规定为：跨工厂 60，同工厂异机器 30，只有工厂和机器都相同才为 0。代码中必须先比较工厂 ID，再比较机器 ID；不同工厂中数值相同的机器 ID 仍是不同资源，仍需支付跨工厂延迟。
- 目标按词典序评估：`makespan`、最大工厂负载、总能耗。
- 输出中的每道工序都必须同时包含 `factory_id` 和 `machine_id`。
- 参考论文使用 Pareto 排序，而当前运行时输出一个固定的词典序最优解。Pareto 档案可用于内部多样性维护，但不能用加权和或任意档案选择替代 Core 的目标顺序。

## 实现

1. 以结构化方式解析候选分组。对每道工序，`candidate_count` 表示跨全部 `F` 个工厂的候选总数。枚举组合 `(g_1,...,g_F)`，其中每个 `g_f` 都落在头部给出的该工厂最小值和最大值之间，且总和等于 `candidate_count`。对工厂 `f`，第一条候选必须是 `f machine duration energy`，随后恰好读取 `g_f-1` 条 `machine duration energy`。验证下一个工厂标记；若存在多种组合可能，就对后续工序回溯。只有在某个回溯分支成功解析全部声明工序并完整消耗整行作业数据时才能接受；尾随多余 token 一律拒绝。每个原始机器 ID 在转成全局 0-based 之前，都必须先验证属于 `1..F*machines_per_factory`。
2. 不要根据数字大小猜测某个 token 是否是工厂标记。加工时间和能耗值可能很小，而机器 ID 使用全局编号，可能大于每工厂机器数。
3. 每个分配都表示为 `(factory,machine)` 对。候选分组里显式给出的工厂标记是权威信息；不能只靠机器值判断工厂块。不同工厂的资源不得合并，也不得局部重编号。
4. 保留重复候选项。选择与校验候选时必须使用 `(factory,machine,actual_duration)`，而不只是 `(factory,machine)`；若输入里有多个三元组完全相同，单位能耗应确定性地取最后一个匹配项。
5. 对作业弧的解码应先比较工厂 ID，再比较机器 ID；资源弧则按完整的工厂-机器对建立。
6. 递增跟踪加工能耗 `duration * unit_energy` 和转移能耗 `delay * 6`，随后再基于选中的合法候选元组完整重算被接受解的能耗。只要自检错误列表非空，该候选就是失败候选，绝不能输出，也不能保留为合法 incumbent。
7. 根据本轮瓶颈选择工厂/机器分配、顺序或解码的一个完整改进机制，不要求一次实现全部 move，始终保留独立完整 incumbent。
8. 报告各目标的增量变化和转移合法性审计。只有在精确模型实际运行过时，才能声称使用了 CP-SAT。

## 方法指引

### 先判断解码是否限制搜索收益

改算法前检查现有解码器是追加到机器末尾，还是允许插入合法空闲间隙。
若仅维护机器最终可用时刻、存在明显空洞，应优先在获准组件内实现完整区间状态
和最早可行间隙插入，先用固定 smoke 验证前后继转运、资源互斥和三目标。
间隙插入不是新方法族：构造可用于派工解码，局部可用于重插邻域，群体可用于后代解码。
只有诊断支持该瓶颈时才优先处理；已有间隙解码则保留，不按算例名选择该机制。
先把一个候选生成、完整解码、接受和 CLI 调用闭环接好，再写更多操作函数。
已存在的方法仅新增计数可以用于诊断，但不能作为本轮新增优化机制的完成证据。
将诊断支持的瓶颈映射到本轮具体函数和调用入口；不要把所有理论邻域一次性重写。
原完整求解器的结果必须与新候选按词典序比较，不能只保留更弱的构造种子作为 fallback。

### 首次搜索必须完成的闭包

解析器已经被固定 Core 验证时，应保留并复用，不要重写或把本轮任务缩减成仅解析输入。
每条正式 lane 必须同时保证候选身份、转运感知完整解码、词典序重算和一个实际执行的搜索机制。
`distributed_transfer_search_bridge` 是前置必做组件：先评价一个非原分配的合法候选或一个新的
调度顺序，完整重解码并运行固定 smoke，随后再扩展所属方法族。评价但未改善也须如实计数；
不能靠仅增加诊断字段、调用未改动的 incumbent 或覆盖原有搜索入口来通过验收。

先保存原算法作为独立完整 fallback，再以小改动接入搜索。Worker 预算前半段仍未完成可达
搜索 smoke 时，缩小为一个同厂换机/跨厂候选替换或有界多起点，不继续搭建大型框架。
不得为了实现新方法把已有有效多起点、搜索循环或时间预算缩短为单次贪心。

### 转运感知的候选评价

- 工厂/机器/加工时长/单位能耗属于同一候选身份，变异必须从完整 eligible 元组中抽取。
- 单点换机至少联合检查前驱与后继转运。更短加工时间可能新增60的转运或进入更拥堵资源，
  不能只凭加工时间差接受；近似增量仅用于候选筛选，最终评分必须完整重解码。
- 对连续工序段尝试同厂聚集、整段迁移和边界机器替换，避免每道工序独立选厂造成反复跨厂。
  这只是搜索候选，不是强制所有工件固定在同一工厂；负载较高时跨厂分流可能更优。
- 转运本身不是独立占用运输设备的活动，不添加当前契约中不存在的车辆/运输资源约束。
- 对新候选重新计算三目标；仅在makespan相等时比较最大工厂负载，再相等才比较能耗。
  不用“转运最少”“工厂最均衡”或“能耗最低”覆盖更优makespan。

- 对 `population_memetic`，保持 OS/FA/MA 的耦合决策，使用 GLR 风格的全局/局部/随机初始化、保持 precedence 的 OS 变异、候选合法的分配变异，以及有界局部搜索。论文里的 60/30/10 初始化比例只能视为可调假设，不能硬编码成答案。
  初始种群至少包含转运感知、同厂段聚集和负载分流的不同结构，不得只扰动OS而FA/MA全部克隆。
  先完成一个合法后代的生成、解码和替换闭环，再扩大种群；替换按运行时词典序执行。
- 对 `coupled_local_search`，实现 LSO_SP、LSO_MPT 和 LSO_RTT 对应的机制：关键块顺序 move、更快的合法工厂-机器替换，以及降低转移代价的替换。每个 move 在接受前都必须完整重解码。
  按瓶颈选择同厂换机、跨厂/工序段替换或关键块重插，停滞后在剩余预算内切换邻域或重启；
  不把只重排输入job顺序的构造称作耦合局部搜索。
- 对 `constructive_search`，使用多个具备转移与负载感知的起点；不要把单一路径的贪心派工称作 memetic 搜索。
- 对 `exact_hybrid`，建模当前激活的三目标运行时契约，或一个边界清晰的修复邻域；超时后必须保留合法的启发式 incumbent。

编辑前先阅读分布式语义卡、搜索卡以及已分配的方法包。

### 接口与失败复验

随机数种子与调度方案是不同类型，不能把方案列表传给随机数生成器。
函数实参按声明的语义传递，调用前核对类型；不能用盲目强制转换掩盖传错参数。
新路径被异常捕获后返回合法fallback不表示算法完成。报告失败阶段与异常信息，
在剩余授权smoke次数内修复再验证；没有剩余预算时明确报告未完成，不宣称激活成功。
计数验收只证明路径执行；必须同时报告相对本轮父算法的实际改动和最终比较结果。

### 停滞后的方向选择

先区分未写出代码、CLI 未到达新机制、解码失败和合法搜索未改善；前三类修执行闭环，
最后一类才调整邻域与接受策略。不要用提高计数或更大的种群掩盖原因。
连续多次同点搜索失败时，在所属方法族内改变结构：局部搜索可从单点替换转为
工序段联合分配或关键块顺序重插；模因搜索检查 FA/MA 多样性及实际后代替换，
避免将多个克隆个体反复完整解码。缓存按完整 OS 和候选身份建立，不能漏掉时长或能耗。
第一轮无改善不是强制换方法族的依据，方法族变更仍由 Main 授权。

## 运行证据

最终JSON的顶层`diagnostics.distributed_transfer`记录`assignment_options_evaluated`、
`candidates_decoded`、`same_factory_moves`、`cross_factory_moves`、`segment_moves`、
`accepted_moves`和最终跨厂弧数。只计真实尝试，不要求所有移动均改善或所有种类均被接受。
同时提供所属方法族的原有激活计数；exact还必须提供真实Solve状态与模型规模。
合法性、makespan、最大工厂负载和能耗以固定Core重算为准，不使用历史目标值或算例名选择参数。
